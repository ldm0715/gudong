# Phase 2：MVP 功能 报告

状态：功能完成，媒体、歌词与内存已实测；页面管理、播放控制与 1 小时挂机等待人工验收。
日期：2026-11-19

## 已实现

### sidecar（Rust）

- [x] `media.rs`：读取 SMTC 会话，优先正在播放的音乐，其次暂停的音乐与其他会话
- [x] 播放中最多 1Hz 推送 `media.changed`；暂停、停止时只在内容变化时推送
- [x] 播放位置按 `LastUpdatedTime` 外推；标题、歌手、专辑、来源、时长、播放状态齐全
- [x] 封面随曲目变化读取一次，转 data URI 下发；晚到的封面每 10 秒补试并补发
- [x] `media.control`：播放 / 暂停、上一首、下一首、跳转；COM MTA 调用有超时保护
- [x] `lyrics.rs`：按歌名精确匹配 QQ 音乐候选，歌手与时长用于同名版本排序
- [x] LRC 解析支持一行多时间戳、排序去重、过滤作词作曲等制作信息
- [x] 切歌后旧歌词请求的结果会被丢弃；抓取中、抓取失败都会给客户端明确状态
- [x] 设置项 `mediaEnabled` 关闭后停止读取媒体，恢复后自动重新拉取
- [x] `tabOrder` / `hiddenTabs` 由配置持久化，sidecar 只存储，不参与 UI 决策

### Flutter

- [x] 媒体页左右分栏：左侧封面、曲名、歌手 / 来源与控制器，右侧 7 行歌词，底部通栏进度
- [x] 歌词当前行高亮，切行用 340ms `easeOutCubic` 整列滚动，不再是硬切
- [x] 进度条拖动跳转；播放 / 暂停、上一首、下一首已接入控制器
- [x] 播放进度由独立 250ms 时钟插值，只重建进度区域，不触发岛体外壳
- [x] 收起态最右侧显示 5 段音波：中间高、两端低，按连续行波起伏
- [x] 音波可在设置中开关，默认开启；暂停或停止时自动卸载并释放动画
- [x] 页面管理：tab 显隐与排序；允许全部隐藏，此时岛体显示空状态与设置入口
- [x] 设置窗口“音乐与歌词”：媒体开关、播放音波开关、刷新频率、封面与歌词来源说明
- [x] 设置窗口保存时合并 `mediaEnabled` / `showPlayingIndicator` / `tabOrder` / `hiddenTabs`，
      不覆盖窗口位置
- [x] 封面按 104px 解码，image cache 上限 32MB，避免长时间切歌后缓存累积

## 性能基线

测量条件：Windows 10 22H2、125% 缩放、release 构建、音乐播放中、未打开设置窗口。

内存口径：任务管理器“内存”列对应 private working set；工作集与提交大小包含
共享 DLL 和预留地址空间，不作为预算口径。

| 指标 | 预算 | 实测 | 结论 |
| --- | --- | --- | --- |
| private working set 合计 | ≤ 80MB | 43.0MB | 通过 |
| 参考：工作集合计 | - | 105.3MB | 含共享 DLL |
| 参考：提交大小合计 | - | 104.7MB | 非常驻占用 |
| 空闲 CPU | ≤ 0.5% | 未复测 | 待测 |
| 冷启动到首帧 | ≤ 1.5s | 1.12s | 通过 |
| 冷启动到窗口可见 | ≤ 1.5s | 1.33s | 通过 |
| 歌词滚动 / 音波帧时间 | < 16.7ms | 未测 | 待测 |

进程明细：

| 进程 | 工作集 | private working set | 提交大小 |
| --- | --- | --- | --- |
| island_app | 79.6MB | 38.7MB | 98.8MB |
| island_service | 25.7MB | 4.3MB | 5.9MB |

对照 Phase 1：合计 private working set 40.7MB。Phase 2 的媒体轮询、歌词与音波
动画带来约 2–3MB 常驻增量；其余仍在 Flutter 引擎基线范围内。

封面按原图解码时，同一会话测得 island_app private working set 为 66.1MB。
修复后重启降到 38.7MB，说明增量来自 image cache，而不是业务状态泄漏。

复测命令：

```powershell
# 需要先退出应用
powershell -ExecutionPolicy Bypass -File scripts\measure-baseline.ps1
```

## Phase 2 已知限制

- 歌词源只有 QQ 音乐；无版权或曲库未收录的歌曲不会显示歌词。
- 同名翻唱、现场版较多时，按歌手与时长排序仍可能匹配到录音室版本。
- 歌词请求依赖网络，失败后要等下一次切歌才会重试。
- 视频会话也会显示在媒体页；只要有标题就会尝试匹配歌词，视频通常匹配不到。
- 部分播放器对 SMTC 跳转只返回成功不实际跳转；酷狗 / 网易云的专用跳转接口未接入。
- 设置窗口打开期间的设置修改不会实时同步回设置窗口，关闭重开即可。
- 开机自启、自定义快捷键、安装包与自动更新留到 Phase 3。
- 微信 4.x 不使用 Windows 通知中心，因此只显示“微信有未读”，没有联系人和内容。
- 动画帧率与输入延迟未实测；页面管理与 1 小时挂机依赖人工验收。

## 过程中修复的问题

- **歌词一直不显示**：最早只对 `kind=music` 抓词，而部分播放器不上报
  `PlaybackType`。改为只要有标题就尝试匹配，并把视频会话的失败视为正常无歌词。
- **歌词加载状态不明确**：切歌后只发一次空歌词，客户端会一直停在“暂无歌词”。
  增加 `pending` 字段，抓取成功或失败都会再发一次结果。
- **媒体页布局**：最初歌词只占一行专辑文字，改为左右分栏，歌词占右侧主要空间。
- **歌词硬切**：改为整列 340ms 缓动滚动，切歌时复位，不会从上一首位置滑入。
- **音波峰值乱跳**：每根竖条使用不同频率，波峰会从中间瞬移到边缘。改为同频率、
  按位置错相位的连续行波，峰值只平滑移动。
- **内存增长**：封面按原图解码并进入 image cache。改为 104px 解码并限制缓存
  上限，长时间切歌后不再持续增长。
- **页面管理开关逻辑错误**：曾按“只剩一个可见页”禁用所有开关，后来又限制
  至少保留一个页面。现在允许隐藏全部页面，岛体改为显示空状态与设置入口，
  不再用消息页兜底。
- **拖动进度条后跳回原位置**：播放器下一帧仍上报旧进度，覆盖了本地目标。
  增加 5 秒的跳转等待：确认前保持在目标位置，确认后再采用播放器进度。
- **常规页重复的天气开关**：与天气页功能重合，删除常规页的“功能”分组。
- **启动慢**：sidecar 进程启动原先排在首帧之后。改为与窗口初始化并行，
  本次采样首帧 1.12s、窗口可见 1.33s。
- **退出卡顿**：退出清理串行等待且部分步骤没有超时，实测从点击退出到下次
  启动间隔 24 秒。现在设置窗口枚举、sidecar 关闭、窗口销毁都有上限，
  并加 2 秒强制退出兜底；退出日志增加 hotkey / tray / scope / window 节点。
